pace 不打算成为"又一个测速工具"。它有明确的服务对象（教育网/
校园网用户，首先是南京大学）和明确的产品边界。这一页把这些选择及其
理由写清楚。

## 教育网优先

大多数测速工具围绕"消费者宽带 + 就近运营商服务器"设计，测出来的是
最好看的那一段路。教育网用户的真实问题却是分段的：校内是否通、
校园 VPN 是否正常、CERNET 出口表现如何、公网/境外方向怎么样。

pace 把 NJU 校园网作为产品主线（`nju-campus`，IPv4/IPv6 独立
测量），把同济等教育网站点作为可选参考方向，把 M-Lab 作为
公网出口视角。这个组合是为"定位慢在哪一段"服务的，不是为跑分服务的。

## 多视角，不打分

不同目标的结果**永远不会**被替换、排名或折算成一个综合分数：

- 校内路径不可达时，不会静默换一个站点凑数；
- NDT7 单流和 LibreSpeed 三并发流的数值不做横向比较；
- 没有任何"网络评分"或加权公式。

理由在[网络测速在测什么](/concepts/what-speed-tests-measure)里展开：
把互相独立的量压成一个数字，必然丢掉定位问题所需的信息。

## 诚实的数据

- 失败的测量记录**零速率**和稳定的失败阶段（`helper` / `dns` /
  `connect` / `download` / `upload` / `timeout`），不伪装成成功；
- 取消后未开始的目标记 `skipped` 与 null 速率，与"试了但失败"严格
  区分；
- CERNET 公共站点当前不可达，就保留显式诊断，而不是移出产品假装
  它不存在；
- M-Lab 返回哪个节点就显示哪个节点，不承诺"一定测到境外"。

## 可脚本化

全局 `--json` 输出恰好一个 JSON 文档、无 ANSI 转义；schema 有版本号；
退出码稳定（`0` 成功 / `1` 配置或环境错误 / `2` 目标失败或部分成功 /
`130` 取消）；历史永久保存为每次一个 JSON 文件，可导出 JSONL/CSV。
定时任务、监控看板、论文数据采集都可以直接消费。详见
[JSON 输出与自动化](/reference/json-and-automation)。

## 隐私：显式同意，fail closed

- M-Lab 会公开并无限期保留测试结果和 ISP 提供的公网 IP。pace
  要求用户**显式**接受其隐私政策后才运行 M-Lab 测试；没有同意记录时，
  非交互命令在接触 M-Lab 前直接以 `consent_required` 失败——宁可
  失败，不替用户做隐私决定。
- LibreSpeed 的遥测和结果分享始终禁用。
- pace 自身没有遥测、没有远程结果服务、没有地理定位和 ASN 查询。
- 历史文件权限 `0600`、目录 `0700`，只存本地。

## 不做的事

清单同样重要：

- 无守护进程、无特权 helper、无账号、无云同步、无自动调度；
- 不捆绑、不自动安装第三方测速程序，不代替用户接受任何第三方条款
  （Apple、Ookla 的条款由用户自己面对）；
- 不维护 Ookla 协议的逆向实现，只调用官方 CLI；
- 不读取或修改 soundVPN、SFM、NJUConnect 的私有配置；
- 不绕过任何站点的浏览器验证。

与其他工具的具体关系（复用谁、对比谁），见
[与其他工具对比](/positioning/comparison)。
